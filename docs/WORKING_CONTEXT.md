# 현재 작업 맥락

이 문서는 여러 작업 대화가 함께 확인하는 임시 인수인계 문서입니다. 확정된 내용은 담당 기준 문서로 옮기고 여기에서는 제거합니다.

## 진행 중

- [16:9 화면 전환] 내부 기준 해상도 `1600×900`, 기본 실행 창 `1280×720`을 최종 유지할지 결정해야 합니다. 실제 1280×720 전투 캡처에서는 스크롤이나 잘림 없이 필드·주문 영역·행동 버튼이 표시되었습니다.
- [대전 레이아웃] 대응 단계의 `피해/처치 직후` 안내를 전투 레이아웃의 행에서 제거하고, 보드를 밀지 않는 화면 오버레이로 옮겼습니다.
- [게임 모드 기반] `기본 모드`와 `운명 모드`를 AI·로컬·온라인에서 공통 선택합니다. 기본 모드는 유닛 덱만 고른 뒤 바로 다음 선택이나 대전을 시작하고 운명 덱·드로우·손패 UI·사용 판정을 모두 끕니다. 운명 모드만 유닛 덱 뒤에 운명 덱을 선택합니다. 온라인 서버는 방에 저장된 모드를 권위 값으로 사용하며 클라이언트의 전투 시작 요청으로 모드를 바꿀 수 없습니다.
- [운명 덱과 전투] 운명 모드의 덱은 12장, 같은 운명 최대 2장입니다. 운명 덱 보관함은 사용자 덱 8칸과 오른쪽 아래의 항상 표시되는 `기본 운명 덱` 1칸을 사용하며, 관리 화면에서는 기본 덱을 복사해 편집할 수 있습니다. 기본 운명 덱은 목록 1~6번을 각각 2장씩 사용하며 7번은 제외합니다. 운명 모드에서 유닛 덱을 선택하면 좌우 전환 연출과 함께 실제 운명 덱 3×3 페이지로 교체됩니다. 게임 시작 시 선공·후공 모두 섞인 덱에서 2장씩 가지고 시작하며, 첫 턴을 포함한 자기 턴 시작마다 1장 더 뽑습니다. 운명을 누른 뒤 비용을 낼 생명을 고르고, 대상이 없는 운명은 즉시 선언하며 대상이 있는 운명은 그 생명에서 이어지는 화살표로 대상을 한 번 선택해 선언합니다. 재충전은 비용을 지불한 생명이 자신의 마나를 1 회복하므로 생명을 한 번 고르면 바로 선언됩니다. 해결된 운명은 사용된 운명 영역으로 이동합니다. 성장·통찰·화염·재충전·방어·자가 치유·파괴 7종을 로컬과 서버 권위 전투, AI 행동과 임시 하단 운명 손패 UI에 연결했습니다.
- [서버 권위 전투 엔진] 실제 Render 서버 저장소 `BestTCGidea_Render_server`의 `src/battle/`에 Node.js 전투 엔진을 작성하고 온라인 판정을 전환했습니다. 서버가 덱 검증·덱과 패·필드·턴·생산·배치·공격·주요 능력과 영혼 효과를 소유하고, 접속 소켓에 배정된 플레이어 번호로 명령 권한을 확인합니다. 상대 덱과 패는 가린 플레이어별 스냅샷을 내려줍니다. Godot의 기존 전체 판정은 `local_battle.gd`로 옮겼고, `battle.gd`는 로컬 판정 호출과 원격 명령·서버 스냅샷을 중계하는 공용 입구가 되었습니다. 화면 입력은 모두 `battle.submit_command()`를 거치며, 온라인에서는 각 클라이언트가 자기 덱과 행동을 Render 서버에 직접 보내고 확정 스냅샷만 반영합니다. 게임 저장소의 기존 `server/battle/` 골격은 옮기지 않고 그대로 둡니다.
- [서버 카드 효과 틀] Render 서버의 사용 가능한 전체 카드(금지 카드 `갬블의 악마` 제외)를 공용 카드 정의와 효과 실행기로 옮겼습니다. `rules.js`는 카드 ID별 효과 분기 없이 생산·피해·처치·공개 같은 공용 사건만 전달하고, 지속·소모·유발·대응·고정 효과는 같은 조건·대상·비용·상태 변경 경로를 사용합니다. 일반 주문은 비용 0 소모 판정을, 가시 골렘·불사조 주문은 사건 직후 대응 창을 사용합니다. 기본 공격과 운명은 유발로 체인에 올라가며 양쪽 연속 패스 뒤 해결합니다. 서버는 유닛 덱과 운명 덱을 함께 검증하고, 섞인 운명 덱·비공개 손패·사용 기록도 권위 상태로 소유합니다.

## 임시 결정

- 카드 내부 UI는 구조와 문구가 더 바뀔 수 있으므로 계속 동적으로 생성합니다. 카드가 들어가는 슬롯과 카드 밖의 화면 틀은 재사용하는 방향을 유지합니다.
- 운명 덱 제작 화면 오른쪽의 운명 카드 표시는 기능 확인용 임시 UI로 두고, 다음 전체 UI 개편 때 함께 다시 디자인합니다.
- 운명 시스템 이전의 카드와 전투 규칙을 `기본 모드`의 기준으로 유지합니다. 추가 규칙은 기본 모드를 직접 바꾸지 않고 별도 모드로 등록합니다.
- 게임 모드 목록은 `src/battle/game_modes.gd`에서 공통 관리하고 AI·로컬·온라인이 같은 모드 ID와 이름을 사용합니다.
- 새 온라인 전투는 Node 서버가 유일한 전투 상태와 판정을 소유하고, Godot 클라이언트는 행동 요청과 확정 상태 렌더링만 담당하는 방향으로 진행합니다.
- 한 턴의 시기는 `시작 → 생산 → 공개 → 주요 → 종료` 다섯 단계로 나눕니다. 배치·피해·사망처럼 단계 안에서 일어나는 일은 별도 사건으로 취급합니다.
- 카드 효과 종류는 임시 명칭으로 `지속`, `소모`, `유발(운명류)`, `대응(불사조 주문류)`, `고정(특정 시점)` 다섯 가지로 나눕니다. 시기와 효과 종류는 서로 독립된 값으로 관리하며, 세부 명칭은 나중에 바꿀 수 있습니다.
- 일반 주문 효과는 별도 여섯 번째 종류로 만들지 않고 `소모`와 같은 판정을 비용 0으로 재사용합니다. 유닛 소모는 해당 유닛의 마나를 내고, 일반 주문은 비용 없이 패에서 사용됨 영역으로 이동한다는 출처·후처리만 다릅니다. 조건부 주문은 `대응`으로 분류합니다.
- YGOPro·EDOPro는 사건 기반 효과 등록, 조건·비용·대상·해결 분리, 선택 대기와 시드 난수 같은 구조적 아이디어만 참고합니다. AGPL 코드를 복사·번역하거나 `ocgcore`를 결합하지 않고, 이 프로젝트의 룰북과 기존 코드만을 기준으로 독자 구현합니다.
- AI는 자동 테스트까지만 실행하고, Godot 화면 배치와 실제 조작 확인은 사용자가 직접 합니다.
- 운명 손패는 기존 대전 하단에 기능 확인용 임시 패널로 표시합니다. 운명 카드의 최종 시각 디자인과 손패가 많을 때의 배치는 다음 전체 전투 UI 개편에서 다듬습니다.
- 새 필드 카드 시안은 장식 전 오각형 몸체를 기준으로 중앙 그림, 왼쪽 마나, 오른쪽 체력, 아래 생산력 영역을 사용합니다. 공용 배치 초안은 `docs/CARD-LAYOUT-SPEC.md`와 `docs/specs/card-layout-spec.json`에 280×280 기준으로 기록했습니다. 위 꼭짓점은 뾰족하게 유지하고, 게이지 두께는 이전 100% 형상의 85%로 두며, 마나·체력 눈금은 바깥 테두리와 직각이고 해당 지점 통 두께의 1/3 길이입니다. 수치 중심은 마나 `(55,220)`, 체력 `(225,220)`, 생산력 `(140,261)`이고 실제 Godot UI 반영은 최종 확인 뒤 진행합니다.
- 새 전투 필드 와이어프레임은 상대·공용·내 진영 모두 6칸을 유지합니다. 공용 줄의 3개 표시는 3칸짜리 줄이 아니라 6칸 중 3칸만 점유한 예시입니다. 상대 손패는 카드 자체를 뒤집지 않고 부채꼴 배치만 상하 반전해 화면 위 바깥에서 내 쪽으로 펼치며 장수를 따로 표시합니다. 필드 유닛은 새 공용 카드 규격을 사용하고 슬롯 여백을 일부 남긴 채 이전보다 조금 크게 표시합니다. 이 배치는 `docs/reference-images/battle-field-6x3-wireframe.png`에서 확인하며 아직 Godot UI에는 반영하지 않았습니다.

## 확인 필요

- [사용자 확인] Godot 디버그에서 덱 보관함, 덱 제작, 대전을 차례로 열어 클릭 전후 위치 유지와 중앙 경고 연출을 확인해야 합니다.
- [사용자 확인] 온라인 방 만들기 화면을 1280×720에서 열어 방 이름, 게임 모드, 설명과 방 만들기 버튼이 잘리지 않는지 확인해야 합니다.
- [사용자 확인] AI와 로컬에서 게임 모드 선택 화면의 배치와 다음·뒤로 이동을 확인해야 합니다.
- [사용자 확인] AI·로컬·온라인의 유닛 덱 → 운명 덱 선택 전환과 대전 하단 운명 손패의 실제 크기·클릭 흐름을 확인해야 합니다.
- 모드 분리와 기본 운명 덱·선택 화면 전환 변경 후 자동 검사는 카드 자동 실패 0, 카드 재작업 39/39, 규칙 2777/2777, AI·로컬 모드와 재충전 단일 선택 13/13, 드래그 실패 0, UI 155/155를 통과했습니다. Render 서버 전체 검사는 기본 모드의 운명 비활성화와 운명 모드 판정을 포함해 31/31을 통과했고, 실제 서버와 Godot 두 클라이언트를 연결한 운명 모드 통합 검사도 실패 0으로 통과했습니다.

## 다음 작업

- 사용자가 세 UI 화면의 위치 유지, 온라인 방 만들기의 모드 선택 배치, AI·로컬 공용 모드 선택 흐름을 직접 확인합니다.
- 16:9 화면 전환의 최종 유지 여부를 결정합니다.
- 운명 카드의 이름·수치·효과와 임시 전투 손패 UI를 실제 플레이로 확인한 뒤 밸런스와 최종 표시를 조정합니다. 현재 금지 카드인 `갬블의 악마`와 룰렛은 해제하기로 정할 때 별도로 이식합니다.
- 서버 재시작에도 대전을 복구할 저장 방식, 재접속, 명령 ID와 중복 방지, 서버 난수의 재현 방식을 정합니다.
